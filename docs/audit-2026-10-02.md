# News Monitor audit — 2 October 2026

Goal: investigate production decisions and improve general freshness/editorial
logic, with saved checkpoints during the requested overnight work window.

## Evidence and changes

- Run 409 (`36839251958`, job `110294216675`) shows the Nantes school fire
  passing keywords for Nicușor Dan and receiving a false political duplicate
  verdict about Bolojan. Recommended Digi24 stories had contaminated the body.
  This happened before the existing carousel exclusion commit. The current
  scraper was checked against the real publisher HTML: 1,236 characters of
  actual fire coverage, no Nicușor/Bolojan/Mureșan contamination, no core keyword
  match, and no political fast path. This incident was not the national-emergency
  exception; it was article-extraction contamination.
- Publication extraction previously accepted the first arbitrary `time` element
  and used permissive `Date` parsing. Such elements can describe updates or other
  articles, and timezone-less WordPress timestamps were interpreted in runner
  UTC. These are verified code weaknesses; the reviewed completed run does not
  prove that they caused every stale story reported by the user.
- Publication now comes from explicit publication metadata, matching main-article
  JSON-LD, or scoped publication elements. Update dates and page clocks are
  excluded; malformed sources do not mask valid alternatives. Conflicting
  publication sources use the oldest valid date conservatively.
- Automatic candidates use a rolling 12-hour publication-age limit, configurable
  with `ARTICLE_MAX_AGE_HOURS`. Fresh news survives midnight. Dates without offsets
  use Europe/Bucharest, and invalid/future timestamps are rejected. Date-only
  sources are conservatively interpreted at local midnight.
- Age is checked at ingestion, before drafting and before delivery. Pending
  approvals which become stale are closed; explicit manual links retain their
  full override. The 24-hour similarity history is unchanged.
- Political fast paths use headline evidence instead of a politician mentioned
  only in the lead. Foreign headlines with incidental Romanian background go
  to relevance review. Short party acronyms match whole words, so AUR does not
  match “restaurant” or “aurii”. Essential text skips captions and date furniture.
- Startup logs no longer print any API-key prefix or length. No credentials
  were committed or added to the automation prompt.

## Same-URL update checkpoint

The feed path previously called `isUrlSeen` before scraping. Consequently, a
publisher could change a proposal into an adoption, resignation into an
appointment, or warning into an actual event at the same canonical article URL,
but the new text never reached the existing stage-change logic. This was a
general blind spot independent of Gemini quality.

Previously delivered URLs are now scraped and content-versioned. Identical
normalized title/body content remains an immediate skip; missing comparison
content also fails closed. A changed version must still pass publication
freshness, keywords, Romanian relevance and full similarity arbitration. The
old stored version remains a candidate during that decision and is replaced
only after successful delivery. Failed, stale, irrelevant and human-rejected
updates therefore do not erase history. Canonical publisher identity still
handles Digi24 slug/route changes, while unrelated IDs remain separate. The
database change is an update of the existing history row after delivery, not a
schema rewrite or bulk production-data operation.

Offline tests cover unchanged/changed/unverifiable revisions, canonical URL
lookup, post-delivery replacement, preserved embedding metadata and unrelated
URLs. The secure environment still exposes no Gemini credential; no live model
or GPT/OpenAI test was made for this checkpoint.

## Canonical-version candidate checkpoint

The same-URL update path exposed a retrieval gap: the old canonical version was
available in history but had no reserved place in the eight-candidate Gemini
batch. Many higher vector scores could crowd it out, especially because
same-publisher vectors deliberately require a stricter threshold to avoid
template false positives. The code would then compare unrelated stories while
omitting the only direct before/after evidence.

Candidates now carry canonical article identity (including stable numeric IDs
across Digi24 route/slug changes). One existing batch slot is reserved for the
prior canonical version before vector, lexical, pending-approval and recency
selection. The total batch remains capped at eight, so this adds no model call
or request-volume increase. Retrieval logs label this evidence
`same-url-version`. Offline selection tests use twelve stronger distractors and
confirm that the prior version remains first in the review batch. Full Node 22
Actions validation remains authoritative; no secure Gemini credential is
available locally and no live model request was made.
